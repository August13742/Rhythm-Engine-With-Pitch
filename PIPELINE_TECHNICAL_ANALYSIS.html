Technical Implementation Details

1. Audio Pre-Processing

def _prepare_audio(input_path: str, temp_dir: Path) -> str:
    """Normalizes audio to -1.0 dB to ensure BS-Roformer activates correctly."""
    y, sr = librosa.load(input_path, sr=44100, mono=False)
    peak = np.max(np.abs(y))
    target_peak = 0.9  # -1.0 dB approx
    
    if peak < 0.8 or peak > 1.0:
        gain = target_peak / peak
        y = y * gain
        
    sf.write(str(clean_wav), y.T, 44100, subtype='FLOAT')
Why Normalize? BS-Roformer's neural network was trained on normalized audio. Input levels that are too quiet or too hot can cause the model to underperform or clip. Targeting -1.0 dB gives headroom while ensuring sufficient signal strength.

Polyphony Detection: The system automatically detects choir/duet tracks by comparing the RMS ratio between lead and backing vocals. If backing_rms / lead_rms > 0.15, the track is flagged as polyphonic, triggering specialized transcription logic.

Multi-Pass Consensus Algorithm

The multi-pass consensus eliminates octave errors by running transcription at multiple pitch shifts:

def multipass_consensus(audio_path):
    # 1. Transcribe original
    base_notes = basic_pitch.transcribe(audio_path)
    
    # 2. Create +12 semitone shifted audio
    y_plus12 = librosa.effects.pitch_shift(y, sr=sr, n_steps=12)
    notes_plus12 = basic_pitch.transcribe(y_plus12)
    # Shift back: each note.pitch -= 12
    
    # 3. Create -12 semitone shifted audio
    y_minus12 = librosa.effects.pitch_shift(y, sr=sr, n_steps=-12)
    notes_minus12 = basic_pitch.transcribe(y_minus12)
    # Shift back: each note.pitch += 12
    
    # 4. Vote: Keep notes that appear in at least 2/3 passes
    for note in base_notes:
        votes = 1  # Base has it
        if has_match(notes_plus12, note, tolerance=0.1s, 0.5st): votes += 1
        if has_match(notes_minus12, note, tolerance=0.1s, 0.5st): votes += 1
        if votes >= 2:
            consensus_notes.append(note)
Why 3-Pass Consensus? Neural pitch detection models often make octave errors (±12 semitones). By pitch-shifting the input and re-transcribing, genuine notes appear at the same pitch in all passes, while octave errors shift by 12/24 semitones and fail to match.

DSP Grounding (Transient Alignment)

ML models can output notes slightly off from the actual attack transient. The TimingCorrector class aligns each note to the nearest audio onset: 

@staticmethod
def ground_events(events: List[NoteEvent], audio_path: str, window: float = 0.1):
    """Snaps event times to nearest audio transient within window."""
    y, sr = librosa.load(audio_path, sr=22050)
    onset_env = librosa.onset.onset_strength(y=y, sr=sr)
    onset_times = librosa.onset.onset_detect(onset_envelope=onset_env, sr=sr, units='time')
    
    for event in events:
        # Find closest onset within ±window
        candidates = [t for t in onset_times if abs(t - event.time) < window]
        if candidates:
            closest = min(candidates, key=lambda t: abs(t - event.time))
            # Only snap backwards (anticipation feels worse than lateness)
            if closest <= event.time:
                event.time = closest
    
    return events

Adaptive Sieve Algorithm

The sieve ensures playability by enforcing density limits while preserving musical structure:

def _filter_adaptive_sieve(events, difficulty):
    # 1. Cluster notes by quantized time (5ms tolerance for chords)
    clusters = group_by_time(events, tolerance=0.005)
    
    # 2. Polyphony Pass: Keep only top N notes per cluster
    for cluster in clusters:
        if len(cluster.notes) > max_poly:
            cluster.notes = sorted(cluster.notes, key=lambda x: x.velocity, reverse=True)[:max_poly]
    
    # 3. Dynamic Decimation (Speed Limit)
    last_time = -10.0
    for cluster in clusters:
        dt = cluster.time - last_time
        
        # Burst Logic: Allow brief dense sections
        if dt < base_min_interval:
            if dt >= abs_min_interval and burst_duration < 400ms:
                ALLOW  # Burst passes through
            else:
                SKIP   # Decimate - find next valid cluster
        else:
            KEEP
            last_time = cluster.time

🤖 ML Model Usage & Evolution

Current Production Models

BasicPitch (Torch) ACTIVE

Purpose: Polyphonic instrument transcription (piano, guitar, bass, vocals harmonies)

Architecture: CNN-based frame classifier with onset detection head

Key Insight: Excellent onset detection but prone to octave errors → Mitigated with multi-pass consensus

  • Weights: basic_pitch_pytorch_icassp_2022.pth
  • Input: Mono audio @ 22050Hz
  • Output: Note events with (start, end, pitch, amplitude)

FCPE (Fast Context-aware Pitch Estimation) ACTIVE

Purpose: High-fidelity monophonic vocal pitch tracking

Architecture: Frame-level F0 estimator with temporal context

Key Insight: Superior pitch accuracy for single-voice singing; used as primary vocal model

  • Library: torchfcpe
  • Decoder: local_argmax (threshold=0.06)
  • Range: 50-1100 Hz

RMVPE (Robust Monophonic Vocal Pitch Extraction) ACTIVE

Purpose: Fallback/hybrid pitch estimation for vocals

Architecture: Modified HuBERT-based pitch extractor

Key Insight: More robust to background noise than FCPE; used in Hybrid mode

  • Weights: models/rmvpe.pt (auto-downloaded)
  • Threshold: 0.03-0.05

Madmom (DBNBeatTracker) ACTIVE

Purpose: BPM detection and beat tracking

Architecture: RNN + Dynamic Bayesian Network

Key Insight: Most accurate beat tracker; requires compatibility patches for Py3.10+

🔬 Trial & Error History

The current V3.0.0 architecture emerged from multiple failed approaches, each teaching valuable lessons about audio analysis and game design.

Deprecated Approach 1: Non-ML Feature Freeze (V1.08)

Librosa pYIN + Onset Envelope DEPRECATED

Location: deprecated/Non-ML-FeatureFreeze/generator.py

Approach: Pure DSP using LibROSA's pYIN for pitch detection and onset_strength for timing

Why It Failed:
  • pYIN had ~30% octave error rate on sustained vocals
  • Onset detection missed soft attacks (legato passages)
  • No polyphony support - could only detect one pitch per frame
  • "Virtual Voice Diarization" was brittle and song-dependent
What Was Salvaged:
  • Psychoacoustic voting system (coincidence boosting)
  • Dynamic hierarchy analysis (rhythm vs melodic driver detection)
  • Hold duration measurement via RMS decay tracking

Deprecated Approach 2: Whisper + CREPE Hybrid (V3.06)

faster-whisper + torchcrepe + pYIN Voting DEPRECATED

Location: deprecated/FailedWhisperAttempt/generator.py

Approach: Use Whisper ASR for syllable timing, CREPE for sung pitch, pYIN as tiebreaker

CONFIG = {
    "voting": {
        "min_vocal_prob": 0.25,      # Whisper text probability
        "voting_tolerance": 2.5,     # Semitones allowed between Crepe and pYIN
        "crepe_high_confidence": 0.85,
        "octave_error_tolerance": 12,
    }
}
Why It Failed:
  • Whisper's word timestamps had 50-200ms jitter (too coarse for rhythm games)
  • CREPE + pYIN disagreement caused 15% note rejection (false negatives)
  • Rap vocals created noise (Whisper treats fast delivery as continuous)
  • Dependency bloat: faster-whisper added 2GB CUDA overhead
What Was Salvaged:
  • P-Center alignment (acoustic onset correction)
  • Consensus voting architecture (evolved into multi-pass)
  • Latency offset compensation (-18ms typical)

Deprecated Approach 3: 3-Stem / 4-Stem Separators

Demucs / Spleeter Based Separation DEPRECATED

Location: deprecated/3StemFeatureFreeze/, deprecated/4StemFeatureFreeze/

Why It Failed:
  • 3-stem (vocals/drums/other) pooled guitar+piano+bass → poor instrument identification
  • 4-stem added bass but still lost guitar/piano distinction
  • SDR scores 2-3 dB worse than BS-Roformer
Migration Path: BS-Roformer's 6-stem model solved all issues with a single model switch.

CREPE Integration Attempt

torchcrepe as Primary Vocal Model DEPRECATED

Location: deprecated/CrepeFeatureFreeze/

Why It Failed:
  • CREPE outputs continuous F0, not note events → Segmentation added 50ms timing variance
  • Viterbi decoder was CPU-bound (3x slower than FCPE)
  • Low-frequency response poor below 80Hz (missed bass vocals)
Current Status: CREPE is still available in CouncilV2 as model_type="crepe" but benchmarks show FCPE outperforms it on the Kiritan dataset (F1: 0.82 vs 0.76).
