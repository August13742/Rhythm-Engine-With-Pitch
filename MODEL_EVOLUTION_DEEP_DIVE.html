Why Whisper Failed for Rhythm Games

  1. Timestamp Resolution: Whisper outputs word-level timestamps with 50-200ms jitter. Rhythm games need ±20ms accuracy.
  2. Sung vs Spoken: Whisper was trained on speech, not singing. Melismatic passages (multiple notes per syllable) confused the model.
  3. Rap Handling: Fast delivery caused Whisper to merge words, losing boundary information entirely.
  4. Overhead: The CUDA model added 2GB memory overhead and 3-5s initialization per file.

F0-to-NoteEvent Segmentation

A critical challenge was converting continuous F0 curves into discrete NoteEvents. The current V2 segmenter uses onset-aware splitting:

def f0_to_note_events_v2(f0, audio, sr, hop_length):
    """
    Key Improvements over V1:
    1. Uses spectral onset detection for note boundaries
    2. Applies median filter (5 frames) to remove vibrato jitter
    3. Combines onset + pitch change for robust splitting
    4. Handles portamento (only splits on onset OR large jump)
    """
    
    # 1. Energy gate (remove silence artifacts)
    rms = librosa.feature.rms(y=audio)[0]
    f0[rms < 0.10] = 0
    
    # 2. Onset detection
    onset_env = librosa.onset.onset_strength(y=audio, sr=sr)
    onset_frames = np.where(onset_env > threshold)[0]
    
    # 3. Median smoothing (removes vibrato without losing legit pitch changes)
    midi_smooth = signal.medfilt(midi_float, kernel_size=5)
    
    # 4. Split logic
    for frame in range(len(f0)):
        pitch_change = abs(current_pitch - running_median)
        is_onset_nearby = any(j in onset_frames for j in range(frame-2, frame+2))
        
        # Split on: (onset + mild pitch change) OR (large pitch jump alone)
        should_break = (is_onset_nearby and pitch_change > 0.6) or (pitch_change > 2.0)
        
        if should_break:
            emit_note(curr_start, frame, median(pitches))
            start_new_note(frame)
Design Decision: The 0.6 semitone threshold for onset-triggered splits was tuned empirically. Lower values caused over-segmentation on vibrato; higher values missed legato note changes.

Voting Logic Implementation

def multipass_consensus(audio_path, model_path, **kwargs):
    # Pass 0: Original transcription
    base_notes = predict(audio_path, ...)
    
    # Pass 1: +12 semitone shift
    y_shifted = librosa.effects.pitch_shift(y, sr=sr, n_steps=12)
    notes_plus12 = predict(temp_path, ...)
    # Correct pitch: note.pitch -= 12
    
    # Pass 2: -12 semitone shift  
    y_shifted = librosa.effects.pitch_shift(y, sr=sr, n_steps=-12)
    notes_minus12 = predict(temp_path, ...)
    # Correct pitch: note.pitch += 12
    
    # Voting
    for note in base_notes:
        votes = 1
        
        # Check +12 pass
        for n1 in notes_plus12:
            if abs(note.time - n1.time) < 0.1 and abs(note.pitch - n1.pitch) < 0.5:
                votes += 1
                break
        
        # Check -12 pass
        for n2 in notes_minus12:
            if abs(note.time - n2.time) < 0.1 and abs(note.pitch - n2.pitch) < 0.5:
                votes += 1
                break
        
        if votes >= 2:
            consensus_notes.append(note)

Drum Transcription: Grid Decimation

Drum transcription uses DSP-based onset detection with aggressive decimation to achieve a "quarter-note feel":

def _transcribe_drums_onset(self, audio_path):
    # 1. Onset strength envelope
    onset_env = librosa.onset.onset_strength(y=y, sr=sr)
    
    # 2. Peak picking with strict parameters
    # delta=0.45 (vs default 0.1) - only strong hits
    # wait=6 (vs default 1) - minimum ~60ms between hits
    peaks = librosa.util.peak_pick(onset_env, delta=0.45, wait=6)
    
    # 3. Grid decimation (BPM-aware)
    quarter_note_dur = 60.0 / self.bpm
    decim_window = quarter_note_dur * 0.85  # ~85% of quarter note
    
    # Keep only loudest hit within each window
    for next_hit in raw_hits:
        if next_hit.time - current_candidate.time < decim_window:
            # Conflict: keep louder
            if next_hit.velocity > current_candidate.velocity:
                current_candidate = next_hit
        else:
            emit(current_candidate)
            current_candidate = next_hit
Why Decimation Works: Drum rolls and fills sound great in music but overwhelm players in rhythm games. Decimating to quarter-note grid preserves the "beat feel" while keeping note density manageable.

Lane Allocation: Pitch-to-Lane Mapping

def _allocate_lanes(events, n_lanes):
    """Maps notes to lanes using hybrid absolute/relative positioning."""
    last_pitch = 60  # Middle C
    last_lane = n_lanes // 2  # Start center
    
    for event in events:
        pitch_delta = event.pitch - last_pitch
        
        if abs(pitch_delta) > 12:
            # OCTAVE JUMP: Use absolute mapping
            # Map MIDI 40-80 to lanes 0-(n-1)
            normalized = (event.pitch - 48) / 36.0  # ~2.5 octaves
            lane = int(normalized * (n_lanes - 0.01))
        else:
            # MELODIC MOVEMENT: Relative to last
            if pitch_delta > 2:
                move = +1
            elif pitch_delta < -2:
                move = -1
            else:
                move = 0
            
            lane = clamp(last_lane + move, 0, n_lanes - 1)
        
        last_pitch = event.pitch
        last_lane = lane
Design Philosophy: Players develop muscle memory for melodic motion. By using relative movement for small intervals and absolute positioning for jumps, the chart "feels" like the melody rather than random lane assignments.

Evaluation Metrics

def evaluate(pred, truth, tol_time=0.1, tol_pitch=0.6, align=True):
    """
    Greedy matching evaluation with auto-alignment.
    
    Parameters:
    - tol_time: 100ms window (typical human reaction time)
    - tol_pitch: 0.6 semitones (minor tuning variance allowed)
    - align: Enable auto-offset correction to handle model latency
    
    Returns:
    - precision: TP / (TP + FP) - How many predictions were correct?
    - recall: TP / (TP + FN) - How many truths were found?
    - f1: Harmonic mean of precision and recall
    - pitch_err: Mean pitch deviation of matched notes (semitones)
    """
    
    # Auto-alignment: Find best time offset (-2s to +2s, 50ms steps)
    if align:
        best_offset = find_best_alignment(pred, truth)
        for p in pred:
            p.time -= best_offset
    
    # Greedy matching
    matched_truth = set()
    for p in pred:
        for i, t in enumerate(truth):
            if i in matched_truth:
                continue
            if abs(p.time - t.time) < tol_time and abs(p.pitch - t.pitch) < tol_pitch:
                matched_truth.add(i)
                break

Parameter Sweep Protocol

Systematic testing of BasicPitch thresholds followed this protocol:

  1. Calibration Run: Run with default params, auto-align to find global offset
  2. Grid Search: Test all combinations of onset=[0.2-0.5] × frame=[0.2-0.4] where frame ≤ onset
  3. Apply Calibration: Add the learned offset to all sweep runs
  4. Rank by F1: Primary metric; precision tiebreaker
  5. Recommend: Pick highest recall among configs with precision > 0.4

💡 Key Lessons Learned

1. Model Specialization Beats Generalization

Using FCPE (vocal-specialized) + BasicPitch (polyphonic-generalized) + Librosa (percussion-optimized) outperformed any single "universal" model by 15-20% F1.

2. Consensus > Threshold Tuning

Multi-pass voting eliminated more octave errors than any amount of threshold tuning. A mediocre model run 3x with consensus beats a tuned model 1x.

3. Latency Compensation is Critical

Every ML model has inherent latency bias (~8-20ms early). DSP grounding to audio transients is essential for chart "feel".

4. Whisper ≠ Timing Source

ASR models optimize for word accuracy, not timestamp precision. Even "word-level timestamps" have 50-200ms jitter unsuitable for rhythm applications.

5. Separation Quality > Transcription Quality

Upgrading from 4-stem to 6-stem separation improved overall pipeline accuracy more than any transcription model change. Clean stems = clean notes.
